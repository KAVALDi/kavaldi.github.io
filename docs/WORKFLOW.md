# Рабочий процесс

Все команды выполняются в корне этого репозитория. `npm run hub -- <команда>`: то же, что `node src/cli.mjs <команда>`.

## Импорт

**В студии** (`npm run studio`): вкладка "Импорт и разбор" → вставить текст или перетащить `.md`/`.txt` → "Разобрать".

**Из командной строки**: файл или целая папка заметок (например, папка vault Obsidian):

```bash
npm run hub -- import "D:/заметки/Идеи.md"
```

Каждый материал попадает в очередь разбора. Дальше по шагам:

1. **Проект.** Предлагается по ключевым словам проекта (`keywords`) и названиям его записей. При малой уверенности студия просит проверить выбор.
2. **Совпадения.** Список близких записей с оценкой похожести и общими словами.
3. **Действие.** Создать, обновить, связать, отложить или пропустить. Система предлагает одно, решение за вами.
4. **Черновик.** Источник раскладывается по разделам: "Суть", "Назначение", "Предлагаемые механики", "Известные факты", "Гипотезы", "Открытые вопросы", "Возможные противоречия", "Следующий шаг". Разделы источника с узнаваемыми заголовками попадают в одноимённые. Остальное дословно идёт в "Материал источника". Это механическая раскладка, а не анализ смысла.
5. **Одобрение.** Запись сохраняется приватной. Прежняя версия уходит в историю.

Особые случаи:

- **Тот же текст ещё раз**: распознаётся по хешу, предлагается "Пропустить". Создать вторую запись по нему нельзя.
- **Новая версия того же материала**: распознаётся по совпадению текста от 30%. Предлагается обновление записи, созданной по прежней версии, с трёхсторонним слиянием: ваши правки сохраняются, расхождения показываются списком.
- **Сбой или закрытая вкладка**: черновик разбора остаётся в очереди (`drafts/`) и переживает перезапуск.

## Публикация

Разрешение на публикацию: отдельное действие: кнопка "Разрешить публикацию…" на странице записи или

```bash
npm run hub -- allow <id записи>
```

Отозвать: кнопка "Отозвать публикацию" или `npm run hub -- revoke <id>`.

Выпуск (экспорт → сборка → проверка приватности):

```bash
npm run release
```

Посмотреть результат:

```bash
npm run serve
```

Отправить на сайт: обычный Git. Перед коммитом прочитайте diff каталога `content/`: это ровно то, что станет публичным.

```bash
git add content && git commit -m "Обновление материалов"
```

```bash
git push
```

Сборку и выкладку выполняет GitHub Actions (`.github/workflows/deploy.yml`) при попадании изменений в `main`.

### Подключение GitHub Pages (один раз)

Сейчас Pages в репозитории настроен на выдачу файлов из ветки `main`. Сайту нужен источник "GitHub Actions": Settings → Pages → Build and deployment → Source → **GitHub Actions**. То же из командной строки:

```bash
gh api -X PUT repos/KAVALDi/kavaldi.github.io/pages -f build_type=workflow
```

После этого слияние ветки разработки в `main` запустит первую публикацию.

### Что именно публикуется

Только записи с разрешённой публикацией из публичных проектов, и только поля из белого списка. Подробности: в [DATA_MODEL.md](DATA_MODEL.md), раздел "Что остаётся внутренним". Проект со скрытым репозиторием держите с `visibility: private`: тогда на сайт не попадёт ни он, ни его записи, ни даже название.

## Сверка с GitHub

```bash
npm run hub -- sync
```

Обновляет у ссылок на PR, Issue и коммиты заголовок, состояние и дату слияния. Состояния записей не меняет, но сообщает о расхождениях вида "PR влит, а в записи код ещё в PR". По этим датам сайт помечает страницы, которые пора сверить с кодом.

```bash
npm run hub -- activity
```

Получает календарь активности для локального предпросмотра. В Git файл не попадает: на опубликованном сайте его получает сборка.

## Резервная копия и восстановление

Хранилище: обычная папка. Есть три уровня защиты:

1. **История ревизий** в `history/` и журнал `log/events.jsonl`: ведутся всегда.
2. **Git внутри хранилища**: студия коммитит каждое изменение. Чтобы хранить копию вне компьютера, добавьте приватный удалённый репозиторий и отправляйте туда (`git remote add origin …`, `git push`). Это действие владельца: автоматически никуда ничего не отправляется.
3. **Полная копия**:

```bash
npm run hub -- backup "E:/backups"
```

Восстановление: скопировать папку копии на место хранилища и выполнить `npm run hub -- validate`.

Экспорт знаний в другой инструмент не требуется: записи уже лежат в Markdown с YAML-frontmatter.

## Obsidian

Папку хранилища можно открыть в Obsidian как vault и править записи там: frontmatter отображается как свойства, `%%комментарии%%` скрыты в режиме чтения. Правила:

- не меняйте `id`;
- `visibility` лучше менять в студии, чтобы действие попало в журнал;
- после правок выполните `npm run hub -- validate`.

Если запись открыта в студии и одновременно изменена в Obsidian, студия откажется сохранять поверх и попросит открыть запись заново.

Работа с реальным приложением Obsidian не проверялась: см. [VERIFICATION.md](VERIFICATION.md).

## Новый проект

Создайте `projects/<id>.md` в хранилище по образцу из [DATA_MODEL.md](DATA_MODEL.md). Он сразу появится в студии, а при `visibility: public`: на сайте.
