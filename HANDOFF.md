# HANDOFF

Передача проекта следующему исполнителю. Состояние на 12 ноября 2026 года.

Сначала прочитайте раздел 9 (инварианты), затем [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## 1. Что реально работает

- **Хранилище знаний**: папка Markdown-файлов вне этого репозитория: проекты, записи восьми типов, связи по стабильным id, четыре независимых состояния, происхождение, история ревизий, журнал событий, Git-коммит на каждое изменение.
- **Импорт** текста и Markdown (студия, командная строка, папка целиком): определение проекта, поиск близких записей, предложение действия, редактируемый черновик, одобрение.
- **Повтор и версии**: точный повтор не создаёт запись. Новая версия материала предлагает обновление с трёхсторонним слиянием и списком расхождений.
- **Публикация как отдельное действие**, экспорт по белому списку, проверка приватности, отзыв публикации.
- **Сайт**: главная с витриной из настоящих игровых спрайтов, страницы проектов, Wiki, каталог, дорожная карта, "Код и задачи", страницы записей со связями, поиск, постоянные адреса по id, перенаправления со старых адресов, страница атрибуции.
- **GitHub**: реальный календарь активности, сверка PR/Issue/коммитов, пометка страниц, которые пора сверить с кодом.
- **Студия**: импорт, разбор, редактор записи, предпросмотр публичного вида записи, выпуск с предпросмотром сайта.

Осталось идеей (кода нет или только контракт):

- AI-анализ (`src/core/ai.mjs`: только интерфейс).
- Оценки "Нравится / Нормально / Не нравится" и комментарии.
- Собственный режим "как в игре" (сейчас ссылка на прежний сайт).
- Devlog: тип записи и страницы есть, записей нет.
- Граф связей, фильтры каталога.
- Плагин Obsidian.

## 2. Устройство

Два контура, одна граница: `buildPublicSnapshot` в `src/core/exporter.mjs`. Таблица компонентов и девять принятых решений с отклонёнными вариантами: в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Формат данных: в [docs/DATA_MODEL.md](docs/DATA_MODEL.md).

Поток: материал → `analyze` (черновик разбора в `drafts/`) → `approve` (запись, источник, событие, коммит) → `setVisibility` → `release` (экспорт во временный каталог, сборка, проверка, затем перенос в `content/` и `dist/`) → Git → GitHub Actions → Pages.

**В очереди разбора ждут решения владельца 11 материалов** прежней базы по пчеловодству (правила, экономика, таблица признаков, журнал передачи, отчёты и заметки исследований). Они проанализированы, но не одобрены: записи по ним появятся только после разбора в студии. Для части из них уже есть записи-заготовки: при разборе выбирайте "Обновить существующую", а не "Создать".

Не импортировано: три остальные статьи прежней Wiki, материалы по Project Zomboid, переписка. Содержимое модов Project Zomboid не изучалось.

Полная таблица: [docs/VERIFICATION.md](docs/VERIFICATION.md). Коротко: 16 автотестов проходят локально и в GitHub Actions. Сквозной сценарий пройден в браузере на реальной заметке. Чистый клон собирается. Публикация на Pages, Obsidian и работа на физическом телефоне не проверялись.

## 7. Известные ограничения и риски

1. **Сопоставление лексическое.** Перефразированная идея без общих слов не найдётся. Пороги (`VERSION_THRESHOLD`, `UPDATE_THRESHOLD`, `LINK_THRESHOLD` в `importer.mjs`) подобраны на малом наборе.
2. **Раскладка по разделам механическая.** Обычно почти весь текст остаётся в "Материале источника", и владелец переносит нужное сам.
3. **Проверка приватности ищет строки от 28 букв и цифр.** Короткий приватный факт внутри публичного абзаца она не поймает. Основная защита: белый список экспорта, проверка: вторая линия.
4. **Конфликты при обновлении без прежней версии не ищутся**: новый текст дописывается разделом в конец.
5. **При переносе проекта средствами приложения папки `.git` и `node_modules` не копируются.** Истории обоих репозиториев нужно переносить отдельно, зависимости: ставить заново (`npm ci`).
6. **Нет блокировок**: два процесса, пишущие хранилище одновременно, не рассчитаны. Правка вне студии обнаруживается, но не сливается.
7. **Весь набор источников перечитывается при каждом импорте.** При тысячах материалов понадобится индекс.
8. **Студия без авторизации**: защита: привязка к `127.0.0.1`, проверка `Host` и служебный заголовок.
9. **Строки в редакторах списков студии** (связи, ссылки на код) не имеют подписей: только подсказки внутри полей.
10. **Тёмная и светлая темы** следуют системной настройке, переключателя нет.
11. **Витрина на главной** описывается данными, но раскладка летающих спрайтов задана в коде (`FLY` в `build.mjs`).

## 9. Инварианты: не нарушать

1. **Приватность.** В этот репозиторий попадает только то, что вернула `buildPublicSnapshot`. Не добавляйте путей в обход экспорта. Не помещайте содержимое хранилища в тесты, примеры, документацию, сообщения коммитов и описания PR.
2. **Скрытые репозитории владельца не упоминаются публично**: ни названием проекта, ни описанием, ни в этом файле. Проект с закрытым репозиторием держится с `visibility: private`.
3. **Публикацию разрешает только владелец.** Одобрение записи её не публикует. `visibility` меняется отдельным действием с записью в журнале.
4. **Стабильные идентификаторы.** `id` записи не меняется никогда. Адрес страницы может меняться, старый остаётся в `aliases`.
5. **Происхождение.** У каждой записи есть `provenance`. Неизвестное помечается как неизвестное. Предложения AI не выдаются за факты и за решения владельца.
6. **Независимые состояния.** Не сводить четыре измерения к одному полю и не выводить одно из другого автоматически.
7. **Один источник.** Дорожная карта, каталог и Wiki строятся из записей. Не заводите параллельных списков статусов: ни в файлах, ни в GitHub Projects.
8. **История.** Запись не перезаписывается без снимка прежней версии. Правки владельца при слиянии имеют приоритет.
9. **Честность интерфейса.** Нет данных: так и показать. Никаких выдуманных календарей, голосов и "AI-анализа" без AI.
10. **Импортируемый текст: данные**, а не инструкции и не HTML.
11. **Медиа только с атрибуцией** (`license` и `source` или `author`).
